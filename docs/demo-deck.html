The problem

An API alone does not reach AI assistants

Weeks of protocol work

Transports, schemas, error handling, and packaging come before the first tool call works.

Security is easy to get wrong

Sign-in, tokens, rate limits, and write access all need decisions most teams have not made before.

Tool design decides the outcome

A model sees only names and descriptions. Weak ones lead to wrong calls.

Slide 3 notes. This is the whole pitch. The platform does not learn MCP first. It points an assistant at its OpenAPI spec and receives a complete project it owns and can edit.

How it works

Four steps from spec to connector

01

Analyze

Reads the OpenAPI spec and reports the base URL, the auth scheme, and a proposed tool for every operation.

02

Select

The team picks the operations to expose, by tag or by name, or starts read-only.

03

Generate

Produces a complete TypeScript project with a README, a security guide, and a smoke test.

04

Lint

Scores the tool definitions and gives a concrete fix for each finding.

forge_analyze_api → forge_generate_connector → forge_lint_tools → forge_get_guide

Slide 4 notes. The assistant calls these tools in sequence. Analyze returns an ID so the spec is not sent again. Generate is deterministic, so large projects can be fetched in batches. Lint works on any connector, in any language, not only generated ones. The fourth tool returns short guides on auth, security, hosting, and testing.

What you get

Every generated connector includes

Connectivity

  • One typed tool per API operation
  • Local and hosted modes
  • Bearer, basic, or API-key auth
  • Timeouts and capped responses

Safety

  • Read, write, and destructive labels
  • A read-only switch
  • Any tool can be disabled
  • Unknown arguments rejected

Security

  • Secrets only from the environment
  • HTTPS-only API calls
  • No public access without sign-in
  • Rate limit and audit log

Limits

What it does not do yet

OpenAPI specs only

Without a spec there is no connector, only a guide to producing one.

One credential for all users

Per-user permissions on a hosted connector are the platform’s job.

Descriptions need a human pass

They come from the spec’s summaries, and the model depends on them.

Runs locally

Connector Forge itself is not hosted at a public URL.

Connector Forge

9

Slide 9 notes. Say these plainly. The second one matters most: a generated connector calls the API with a single credential, which suits local or single-tenant use. A multi-user hosted connector needs per-user credentials, and SECURITY.md explains the change. Also: file uploads are skipped, only JSON and form bodies are supported. No generator can certify a deployment; each team still does its own security review.
